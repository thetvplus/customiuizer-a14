# 安全实施

Use [AGENTS](../../../AGENTS.md) for shared boundaries and the relevant row of [TESTING](../../../docs/TESTING.md#执行分级) for Quick / Standard / Deep routing. Do not reload unchanged instructions or all linked documents.

1. Continue same-chat follow-ups from the established context, including after compaction; reuse base/head, branch, worktree, ownership, authorization scope and verification evidence. Follow [DEVELOPMENT](../../../docs/DEVELOPMENT.md#git-与协作) for discovery triggers; before shared / remote writes refresh only the live facts required by that operation, without restarting task discovery. Trace the changed input, caller, failure path and owner, then implement the authorized result without repeated confirmation.
2. Choose a coherent rollback unit. For an unknown setting/Feature/Hook use the existing `query_aux_data.py context` [entrypoint](../../../docs/TOOLS.md#辅助数据按需查询); reuse its bounded source/owner/process links, then inspect actual callers, lifetime and exception paths. Known source paths need no reindex or task rediscovery. For runtime changes use the affected [architecture contract](../../../ARCHITECTURE.md#运行时不变量); for ROM uncertainty load the [DexSQL workflow](../../../docs/rom-intelligence/DEXSQL.md). Keep REFERENCE_ONLY evidence outside A14 contracts and remap algorithms to verified A14 implementations. Documentation and leaf tools do not require ROM discovery.
3. Apply the Performance-First preferences and hard constraints in [AGENTS](../../../AGENTS.md#产品与取舍), rather than a linear ranking. For critical-path work follow the existing [optimization principles](../../../docs/OPTIMIZATION_GATES.md#关键路径优化原则): identify the trigger, frequency, latency and sustained cost before choosing preparation, reuse, lazy activation or incremental updates. Stop meaningless computation, sampling, listeners and drawing for invisible, occluded or inactive output while preserving required business events and finite handoffs; verify invalidation and release without changing event semantics. Quantify the claimed benefit at the affected layer; do not trade away core functionality for apparent speed or add complexity without actual benefit. Implement the authorized result and meaningful regression coverage. Update affected imports, reflection / XML / R8 references and generated outputs together; avoid unrelated migration or cleanup.
4. Review the complete task diff, select necessary checks by impact and reuse trustworthy results under [evidence reuse](../../../docs/TESTING.md#证据复用). For automated scope selection or device/Hook acceptance use [agent verification](../../../docs/AGENTIC_VERIFICATION.md): run `tools/agent_verify.py plan --base <task-base>`, check actual callers against its bounded routes, and complete the applicable pending layers. Distinguish executed assertions, installed candidate, activated Hook and comparable performance evidence. Do not append Full, all Python tests or APK builds solely because the task is ending. New failures or risks require diagnosis and affected revalidation.

Report the chosen level, actual verification and remaining risks / device checks. Update the existing refinement page only when current decisions or evidence change; do not add a task ledger.
