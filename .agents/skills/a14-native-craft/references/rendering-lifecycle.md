# 绘制与生命周期

用于 Canvas、材质、状态刷新、异步任务和回收；资源边界仍以 [运行时合同](../../../../ARCHITECTURE.md#运行时不变量) 与 [优化门禁](../../../../docs/OPTIMIZATION_GATES.md) 为准。

## 绘制路径

区分输入准备、measure / layout、绘制和系统合成，先找到额外工作从哪里进入一帧。onDraw / dispatchDraw 使用已准备的状态与可复用 Paint、RectF、Path；文本布局、几何和效果对象随实际输入失效重建，不在每次绘制时重复准备。缓存依赖包括真实尺寸、主题 / 字体、配置与 owner，而非仅文件名或某个开关。

只有内容变化或过渡仍在推进时才请求下一帧；稳定、隐藏、detach 后不得留下“无工作但仍 invalidate”的循环。requestLayout 用于真实测量 / 布局变化，避免仅颜色或 alpha 变化就遍历树；岛的有意几何变化仍按现有协调器处理，不能用禁止布局的 Web 规则破坏它。

检查透明叠层、saveLayer、Bitmap / Shader 与 RenderEffect 的面积、数量和更新频率。硬件层和模糊不是默认优化：先有具体瓶颈再做有界交换，结束时恢复自己持有的设置。不要为模仿 Apple 材质开启全局模糊或捕获无关窗口。

Android View 的 alpha / translation / scale 可减少部分布局工作，但其合成、裁切和离屏成本仍取决于实现；不能据属性名断言 GPU 无成本。优化前后在同设备、刷新率和场景下比较帧时间、分配或功耗；60 / 90 / 120 Hz 的整帧时间分别约为 16.7 / 11.1 / 8.3 ms，并非某个 View 可独占的预算。静态代码检查不能证明设备收益。

## 所有权与失效

每个回调、监听、Animator、采样和图像请求都有明确 owner 与有限生命周期。创建、替换、配置变化、不可见和 detach 的转移须闭合；弱引用只能避免部分强持有，不能代替取消任务、注销监听和释放图形资源。

异步结果先验证来源、当前 owner 和 generation，再提交可见状态；取消不等于不会再收到回调。旧结束回调只释放自己持有的句柄，不移除新窗口、不恢复已被新 owner 改写的属性。尽量沿用项目现有的身份、快照和租约机制，不引入第二套全局管理器。

View 状态在正确的 UI 线程提交；磁盘、反射、同步 Binder 和解析按既有冷路径准备。不把后台任务完成等同于 View 仍有效，也不为轮询状态增加常驻计时器。关闭功能、隐藏和会话丢失后的资源行为按功能合同核验。

Telegram Android 的 attach / detach 配对和 Desktop 的回调寿命说明用于启发 Android 所有权审查；不引入 ImageReceiver、Qt、RPL、C++ 命名或 Desktop 的任务队列 / 注释配额。

## 验证边界

先使用现有针对性回归与可信证据。只有本次结论需要设备测量时才按当前授权使用 Perfetto / ADB / profiler；普通界面审查不自动开全部 MCP、扫描 ROM 或抓 trace。报告实际测过的设备和场景；未测的峰值、长期内存、帧率与宿主兼容保持待验。
