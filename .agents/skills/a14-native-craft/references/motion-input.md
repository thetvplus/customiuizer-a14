# 动效与输入

用于增加、调整或审查反馈、形变、跟手和退场；窗口命中约束先查 [对应功能](surfaces.md)。

## 动效决策

先指出它解释的状态变化、操作反馈或空间关系。高频操作不额外让用户等待；“没有必要新增动画”可以是完成结果。入场、内容交接、提交、取消和退场可有不同节奏，但不能用统一套数值替代原有状态语义。

以当前源码的时钟、曲线和参数为起点。岛以 [IslandMotion](../../../../app/src/main/java/tv/withaibuild/customiuizer/mods/island/IslandMotion.kt) 与 [IslandMotionCoordinator](../../../../app/src/main/java/tv/withaibuild/customiuizer/mods/island/IslandMotionCoordinator.kt) 为入口；不要在 Skill 中维护一份时长表。已有 300 ms 以上的原生协调动画，不能仅因 Emil 的 Web 预算被判错或机械缩短。

响应从当前呈现位置开始，必要时沿用有效速度；抓取点不跳到中心。重定向、快速反向和重复事件不能从旧目标或零进度重播。沿用现有有限时钟及终态处理，不为“更弹”另加常驻弹簧循环。以经过时间推进，核验不同刷新率，不把每帧固定增量当作速度。

几何、裁切、内容和触摸区域应描述同一次呈现；逻辑上设置了目标不能证明屏幕已达到目标。属性动画完成、取消回调、窗口解绑分别核对当前 owner / generation；旧回调不得提交新会话的终态。绘制性能和释放见 [绘制与生命周期](rendering-lifecycle.md)。

系统比例为零、简化模式或不可见时按 A14 既有规则收敛；使用 ValueAnimator 已处理的系统时长比例时，不再手动重复缩放。需要实际布局尺寸变化时不能一律用 scale 替代；也不将 CSS 的 transform / opacity 直接视为 Android 的性能保证。

## 手势审查

- **DOWN：** 记录有效 pointer、局部 / 屏幕坐标、抓取偏移和当时的 owner；只有真实热区接受输入，不能因外层窗口更大就拦截整片状态栏。
- **MOVE：** 依现有方向判定和阈值选择意图，保持跟手。区分位置与速度单位；阈值来自当前功能，不修改全局 touch slop。考虑事件合并、pointer 切换与父容器拦截。
- **UP：** 按实际位移、速度与当前会话提交；一次用户意图只触发一次动作。已判定为拖动的手势不能因为未达提交距离而意外转成点击。
- **CANCEL / 失效：** 父容器接管、第二指、owner 替换、锁屏或 detach 均能退出跟踪、回收 VelocityTracker 并取消待动作；不能将 CANCEL 当作 UP 执行打开 / 切歌等操作。

保留原生通知栏、返回、桌面及滚动容器的手势边界；requestDisallowInterceptTouchEvent 仅在当前手势确实归本控件时使用，不永久锁定父级。点击走 performClick / 等价可访问动作；系统触觉按真实提交与当前偏好触发。

## 有意义的验收

按受影响场景选择：快速开关与反向、拖动中更新来源、半程取消、动画中 detach、横竖屏 / Insets 变化、系统动画关闭、RTL 和不同刷新率。记录连续性、最终几何、输入归属与资源释放，源码推断和设备观察分开；不为修改本 Skill 运行这些产品测试。

Telegram 只提供时间推进、失效和语义的观察实例，不复制其动画类或文字分段算法；具体出处见 [来源](sources.md)。
