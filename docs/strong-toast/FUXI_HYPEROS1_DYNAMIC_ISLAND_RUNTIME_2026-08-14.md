# fuxi HyperOS 1 灵动岛运行时记录（2026-08-14）

## 目标与结论

本轮在 Xiaomi fuxi、HyperOS `OS1.0.7.0.UMCTWXM`、Android 14 上追踪系统
`MIUIStrongToast`，不创建额外悬浮窗或常驻服务。最终实现继续复用 ROM 的事件、
内容 View、自动隐藏调用和 `onComplete()` 清理链。

裁切的根因不是普通 `ViewGroup.clipChildren`，而是动画内容越过 ROM StrongToast
`Window` 的 Surface 边界后被系统合成层硬裁切。稳定约束如下：

- 胶囊从第一个可见帧起保持完整高度和 `scaleY = 1`；
- 宿主窗口透明且覆盖完整动画范围，胶囊保留顶部和底部安全余量；
- 顶部只在窗口内做横向形变，并回到屏幕 `y = 0` 的摄像头宽度起点；
- 底部从物理屏幕底边的紧凑胶囊起点横向展开并上移，退出时反向收紧并回到底边；
- 中心弹出只围绕自身中心横向展开和收回，不带上下方向；
- 自动隐藏和手势关闭共用同一退出函数，保证“从哪里来，回哪里去”。

用户在 ADB 结束前确认保守几何版本不再裁切。其后加入的可逆顶部/中心动画、
内容分层淡入和扩大触摸区域只完成了代码、编译和测试验证，必须在下次连接时再做
慢动作视觉与手势验收，不能记作实机通过。

## 窗口与输入证据

实机窗口记录显示 StrongToast 宿主为全屏宽窗口；增加动画安全余量后高度从约
194 px 增至约 223 px。ROM 胶囊约 48 dp，状态栏约 129 px。尽管窗口变高，
输入系统曾报告可触摸区域仍约为 `[0,0][1080,104]`，这解释了视觉胶囊边缘处
难以开始滑动的问题。

最终代码在 View 附着时注册 ROM 窗口级
`OnComputeInternalInsetsListener`，将触摸 Region 限定为胶囊四周的轻量扩展矩形；
分离时移除监听。隐藏接口通过动态代理冷路径访问，不把 API 102 类型带入 API 101
生产签名，也不持有 Activity 或短生命周期 controller。

## 动画机制与 Telegram 参考

参考仅用于动画调度机制与缓动手感：

- 项目：Ajaxy/telegram-tt；
- 版本：tag `air_v2.11.5`，commit
  `d915b1b9ae856eb9eae737d1816d9c05df66b1d3`；
- 许可证：GPL-3.0；
- 原始位置：`src/util/animation.ts` 的“新动画接管并取消旧动画”机制，
  `src/styles/_variables.scss` 的
  `cubic-bezier(0.25, 1, 0.5, 1)` slide 曲线。

A14 代码没有复制 Telegram 源码、CSS 或框架。对应的 Android 实现是复用
`ViewPropertyAnimator`，启动前先 `cancel()` 同一 View 的旧动画，并用
`PathInterpolator(0.25, 1, 0.5, 1)` 获得快速响应、自然减速且不越界的运动。
底部位移和横向形变同样交给 `ViewPropertyAnimator` 的合成层属性，不在每帧修改
padding 或触发布局。新动画到来时取消旧实例，View 分离时复位；热路径不做反射
扫描、磁盘 I/O、Binder 轮询或无界缓存。

## 下次实机验收

1. 顶部首次和连续充电事件：胶囊从摄像头宽度展开，顶部无黑边、无重复播放；
2. 顶部自动隐藏与上滑：都回到屏幕顶边和摄像头起点，无另设消失线；
3. 底部首次 30% 慢放：完整胶囊从底边上移，顶部圆角不缺失；
4. 底部自动隐藏与下滑：都向下退出，负数底部偏移仍可用；
5. 中心弹出：只中心横向收放，无上下位移和任何裁切；
6. 锁屏、横竖屏、刘海宽度不同的设备：运行时安全区、圆角和触摸 Region 正确；
7. 胶囊视觉边缘外 16 dp 开始滑动：手势可接收，同时不抢占大范围状态栏操作。
