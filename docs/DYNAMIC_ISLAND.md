# 动态岛

适用于 HyperOS 1 / Android 14 / libxposed API 102。入口：**系统 → 动态岛**。应用反馈、媒体与通知接管默认关闭；开启相关接入后重启系统界面。系统开关反馈随动态岛模式启用。普通 Toast 的位置、时间和过滤仍在「系统 → Toast」。

## 两种形态与交互

| 形态 | 内容 | 尺寸 |
| --- | --- | --- |
| SHORT / 短岛 | 音乐封面 / 波形、头像、简短系统状态 | 自动首选 184 dp；手动 160–224 dp |
| LONG / 长岛 | 需要较多文字的应用、通知或可安全适配的原生反馈 | 自动按内容最多 240 dp；手动 184–280 dp，且不窄于短岛 |

两者共用 38–44 dp 的高度（默认 40 dp）及完整胶囊端帽。长度主要改变中段；摄像头安全区、原生时钟 / 电量留白、屏幕与 ROM 宽度限制优先。中间留白至少为 40 dp，或实际挖孔宽度加 16 dp，两者取大。没有独立的大卡片、详情面板或媒体按钮。

单击打开播放器 / 对应应用；通知使用仍匹配原条目的原生行点击。「音乐与媒体 → 左右滑动切歌」默认开启，左滑下一曲、右滑上一曲，仅执行当前会话声明支持的操作。该开关可即时关闭两方向切歌并取消待执行操作，点击打开和上滑隐藏保持可用。上滑隐藏当前活动；下滑、长按不打开其他形态。斜向、多指、CANCEL 和未达到阈值的拖动不提交动作；拖动只沿锁定轴作有界形变，不移动摄像头锚点。

旧展开宽度及已移除的图标、状态精简、手势 / 媒体控制偏好不再参与运行时读取。设置进程启动时精确删除这些旧项（包含短键 / 存储键），不清空其他设置；备份导入和导出也排除它。新的切歌开关使用独立的 `system_island_media_swipe`，默认开启，不复用旧手势键；跟随当前 XML 进入偏好目录与备份。无需通过全局偏好契约版本升级清理其他数据。

设置入口位于“系统”的“系统界面”组，紧跟“状态栏”，与通知中心、控制中心同级。页面依次分为显示、动画、显示内容、音乐与媒体、应用五组。动画样式名为“上下”和“中心”，存储编码不变。

## 展示与状态栏

只保留 `IslandActivityController` 的一个模块窗口与 `IslandActivityView`：音乐、短时反馈、通知和十类系统终态全部共用它，不再借用原生 StrongToast 窗口。已删除原生布局适配、图标改写、独立动画及原生抢占 / 去重依存。展示门控为 `IDLE → PREPARED → VISIBLE → EXITING → IDLE`，身份令牌代表一次事件，generation 保护退场回调。

PREPARED 只准备内容，不取得状态栏占用。有效布局、真实 attach、窗口可见、非透明内容、有效绘制区域，以及原生安全状态均成立后，才转为 VISIBLE 并取得占用。`parent != null` 不构成可见证明。锁屏、息屏、控制中心遮挡、布局失败、取消或解绑成对释放；旧窗口 / 旧动画不能恢复新事件下面的状态栏或移除新窗口。

短岛和长岛按实际动画矩阵与窗口偏移计算屏幕边界，只临时隐藏与岛相交的单个图标；未相交图标、分组和排序保持原样。时间、电量容器及其中的 Duo 仅在确实相交时避让。不识别的 ROM 布局不再回退为整条状态栏淡出。叶图标记录在布局更新时精确恢复 / 剔除失效项，最多保留 128 个当前项。隐藏约 320 ms、恢复约 400 ms；硬件绘制且模块允许模糊时，使用有界临时图像和 RenderEffect。已有原生 RenderEffect 不被覆盖，失效或解绑即释放；不支持则退回 alpha，简化或系统动画关闭时直接完成。

勿扰、静音、响铃、振动、深浅色、飞行、NFC、热点、手电、Wi-Fi、移动数据和蓝牙均来自真实终态。初始、重复与过渡态不报成功。一个最新待显示槽固定收集 200 ms；控制中心展开时不在其上绘制、不改变状态栏。收起后只显示仍有效的最新项，从原事件起最多 6000 ms，实际展示不超过剩余期限与常规停留时长。超过期限、锁屏、切用户或所有者销毁即丢弃，不无限重播。

350 ms 内勿扰引发的响铃变化、飞行模式引发的无线关闭只保留主反馈；原生 AudioManager 指令和磁贴仍用于识别独立操作，解除对应因果合并。所有状态统一来自原有系统终态监听，不再把插件的第二份原生提示作为另一种显示或去重来源。

## 原生额头与充电边界

动态岛开启时，在 StrongToastControl 的统一显示入口直接结束该次显示请求，不创建原生额头窗口或动画队列。因此系统反馈只走模块窗口，没有原生额头回退、透明原生窗、原生图标改写或触摸区域适配。未知 StrongToast 内容不伪造成功反馈，也不能把额头带回来。

独立的 `MiuiChargeController` / `MiuiChargeAnimationView` 继续由系统管理，没有新增 Hook 或电池监听。StrongToast 的大型充电视频不再挤进胶囊，也不以额头回退显示；本版未新增自绘充电岛。系统默认和匹配状态栏高度两种模式的原生行为继续保留。

## 音乐、应用反馈与通知

音乐只使用系统已选中的主播放器，进入其来源应用时隐藏，离开后按当前真实状态恢复。播放先等 750 ms；只有已经显示的音乐岛才有暂停后约 2 秒的退场保留期，metadata 更新不续期。在音乐应用内暂停、入场延迟内暂停或由其他提示占用窗口时，不新建暂停音乐岛；快速回桌面和重复暂停快照也不使它闪现。暂停保留期间进入播放器会消费剩余保留期，返回桌面不再重开；真实恢复播放仍按正常入场延迟显示。上滑隐藏绑定同一会话，换曲 / 旧快照不撤销隐藏，真实暂停 / 恢复边沿才重新激活。回调绑定会话及当前控制器，停止、隐私遮挡、替换和销毁时释放；控制中心临时遮挡保留原期限和真实边沿。

普通 Toast 只接入完整、无格式、单行且能完整放下的文字；明确的成功 / 保存路径可精简，其余保持原文。长文、自定义、空间不足、副屏、来源缺失安全条件或挂窗失败时使用原生反馈。封面、头像、图标及明确成功状态精简均为固定行为，不再设开关。十类系统反馈仅按固定名称白名单加载当前 ROM 原生图标。勿扰和静音优先读取挂载的 miui.systemui.plugin 四个原生提示资源；不加载插件代码，不持有控制器或 Context。其余模式或缺少提示资源时读取 SystemUI 原生快捷开关图标（含主题覆盖），再缺失使用 Android 原生信息图标，不手绘替代。每个事件独占 Drawable，统一白色对比。冷路径以至多 96×96 的临时画布测量透明留白，立即释放；仍委托 ROM Drawable 绘制，将实际可见图形归一到 24 dp 单元中的约 20 dp，保留纵横比，不复制或重画图标；测量失败保留原生素材，单元继续限制其边界。相机留白与两侧图标空间完整可用后才出现，不抢占全局图标或其他应用。波形只表示播放状态，不采集音频；暂停、不可见、遮挡或关闭动画后停止刷新。

通知接管默认关闭，只在原生已通过分组、排序、提醒规则并完成悬浮绑定的阶段接入标准消息及有真实封面的图片通知。保留通知中心原件；失败、静默、免打扰、前台、排除、敏感、应用锁、自定义、全屏、汇总、常驻及其他用户内容继续走原生路径。按应用保留悬浮仅影响通知接管。精确 key / 版本识别，重复绑定不延长 4 秒期限；使用内存中公开内容与已加载图标，不读取 URI 或应用数据库。点击交给原生行，不另发 PendingIntent、不直接删除通知，原生 unbind 与弱引用释放维持闭环。

## 音乐手势扩展方案（待桌面取证和实现）

这一节是后续候选方案，当前代码只实现了左右切歌开关，并未提供以下五个独立配置入口。本会话没有 DexSQL 连接或 ROM APK 原始输入，不能把已有 FUXI / CN / TW 记录当作本次重新扫描结果；按任务允许，扩展交给具备样本的桌面 Agent 完成。建议先限定音乐活动，通知 / Toast / 系统终态保留原有单击与上滑行为，不为每种活动重复增加设置。

| 音乐岛手势 | 建议默认 | 可配置范围 |
| --- | --- | --- |
| 上滑 | 收起 / 隐藏当前岛 | 固定，继续走现有 dismiss；不是系统返回键 |
| 左滑 | 下一曲 | 无、播放 / 暂停、单独播放 / 暂停、上 / 下一曲、音量操作、自定义动作 |
| 右滑 | 上一曲 | 同上；左右总开关关闭时两侧均不执行 |
| 下滑 | 无 | 同上，可选系统音量面板 |
| 双击 | 无 | 同上，常用候选为播放 / 暂停 |
| 长按 | 无 | 同上，常用候选为系统音量面板；一次触发一次动作，不默认连发 |

保留当前单击立即打开播放器。只有实际启用双击动作时才等待系统双击超时再确认单击，双击不得同时打开播放器；拖动、多指、CANCEL、退场、内容身份变化、关闭及解绑都取消待确认单击 / 长按。旧媒体手势键继续退役，新配置用独立键，不改变已有备份默认行为。

动作接入应复用 `SubFragment.openMultiAction`、`MultiAction` 和 `GlobalActions.handleResolvedAction` 的现有编辑与自定义 payload；为音乐追加独立动作集合，枚举放末尾，不改既有编号。现有矩阵已有无 `1`、音量面板 `17`、音量加 / 减 `18/19`、播放 / 暂停 `85`、下一曲 / 上一曲 `87/88`，以及应用 `8`、快捷方式 `9`、Activity `20` 和系统开关 `10`。单独播放 / 暂停目前没有完整的通用矩阵分支，不能直接把 KeyEvent 常量填进去后声称可用；需增加明确的共享映射、名称和回归。

媒体操作必须在 `IslandActivityController` 内绑定当前选中 token，并核对实际可见音乐、前台 / 安全状态、session / action epoch 和播放器 action bits，使用同一 `MediaController.TransportControls` 的 `play` / `pause` / `skipToNext` / `skipToPrevious`；不要退回向全系统发媒体键，以免操作另一播放器。不支持的操作不执行。音量增减先区分本地 / 远程播放与固定音量，优先跟随当前 controller；系统音量面板及应用 / 快捷方式等走现有受限动作入口，失败局部结束，不另找宽泛反射 fallback。平台契约见 [TransportControls](https://developer.android.com/reference/android/media/session/MediaController.TransportControls) 与 [MediaController](https://developer.android.com/reference/android/media/session/MediaController)。

桌面取证复用 [DexSQL 指引](rom-intelligence/DEXSQL.md)、[现有音乐接入查询](../tools/dexsql/island_activity_contract.sql) 和新增的 [音乐手势查询](../tools/dexsql/island_music_gestures.sql)。输入为带哈希的 CN / TW SystemUI、对应插件和 boot framework；先查 schema / 定义来源，再核对 NotificationMediaManager 的选中会话、TransportControls 能力与既有音量面板调用链。FUXI 旧记录中的 `MiuiVolumeDialogImpl.showVolumeDialogH(I)` 仅作候选线索，不替代当前样本。保存版本、file_id、描述符、调用者、匹配数量和 Smali；缺输入或多候选保持 CANDIDATE，不新增猜测 Hook。

实现后把新键加入源 XML、语义目录和偏好备份，再用既有流程更新进程矩阵；没有新增 Hook 时不虚构安装点。验证须覆盖五手势独立映射与“无”、上滑固定、双击不兼发单击、拖动取消长按、左右总开关、配置变更取消旧操作、会话替换 / 不支持动作、通知抢占，以及本地 / 蓝牙 / 远程音量。所有者更换与暂存手势必须闭环释放，目标 HyperOS 实机另验收。

## 动画与资源

模块窗口只有一个有限 ValueAnimator 时钟，五个标量通道描述物理宽、高、位移和透明度。解析临界阻尼模型以物理像素保留当前位置 / 速度，目标改变不重置速度；常规进入 360 ms、变长 / 收缩 320 ms、取消回位 280 ms、退出 300 ms；音乐与第二活动的交接放缓为 440 ms，内容层稍后渐入。“中心”只改变横向宽度和透明度，高度与纵向位置全程固定；不加上下回弹。“上下”保持完整宽高，从顶部进入并向顶部退出，不再共用中心收窄退场；中断 / 重入沿用同一有限时钟和旧回调失效机制。摄像头下限和安全宽度约束优先，终点没有胶囊 / 面板算法切换。图标、文字、波形反向补偿非等比形变，维持物理比例和 16 dp 边距；新文字等有足够空间后在同一时钟中出现。

进入可选上下滑动或中心扩展。中心扩展从首个可见帧即保持最终胶囊高度，以同高小圆胶囊为起点横向伸展；退出反向横向收窄至同高圆胶囊并淡出，保持纵向位置，不同时放大或压缩宽高。所有活动直接使用同一个模块窗口、视图与动效实现。简化模式和系统动画关闭时直接设置正确终态。没有新线程、轮询、无界缓存或动画库。Surface 四边统一保留 80 dp 有界绘制外扩，不扩大逻辑点击框，避免 A14 输入区域因非对称 inset 移位。

已制作真实 View / Path 的 60 / 120 Hz 主机采样、完整进出及反转关键帧，检查位置 / 速度连续、端帽和内容比例；这不是设备 FPS 测量。不再有原生胶囊动画路径或退场连接层。

设计研究：[Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities)、[WWDC23 Dynamic Live Activities 7:37–14:16](https://developer.apple.com/videos/play/wwdc2023/10194/)、[Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/) 与 [Android Spring Animation](https://developer.android.com/develop/ui/views/animations/spring-animation)。开源参考 [dynamic-island-android](https://github.com/Arnav-Dugad/dynamic-island-android) 的运动 / 状态 / 轮廓思路；该仓库没有独立授权文件可确认代码复用，本版未复制其源码、素材或参数，也没有引入 Compose。这里的时间与参数是本模块的候选值，不是 iOS 官方数值。

## Dock 与模糊

| 机制 | 开关与失效范围 |
| --- | --- |
| Android BlurController | 模块 `system_disable_window_blurs` 与系统 `disable_window_blurs` 取 OR；不覆盖用户开关 |
| Launcher BackdropBlurRelativeLayout | 私有材质可能选择 Google 跨窗口或 MIUI 后端；支持能力不等于当时有模糊 |
| DockGlassBackdrop / Optics | 仅采样壁纸合成层并以 Shader 绘制，不是全局窗口模糊，不采集应用窗口 |
| 状态栏 RenderEffect | 模块自己的短时覆盖画面；模块禁用模糊时使用 alpha |

桌面 Dock 可选全宽底栏、原生材质和壁纸采样玻璃，图标位置与点击范围保持。采样每个装饰最多一张受尺寸限制的纹理、一个在途请求；动态壁纸刷新最多 30 Hz，隐藏停止。采样 / Shader 失败一次即退役该采样器，使用原生材质与着色回退；替换、隐藏、配置失效及 detach 释放 Bitmap / Shader / 回调。不为 Dock 重新开启全局模糊，也不因静态检查宣称更流畅。

验证、变更统计、独立审查及回退单位见 [A14 精修路线图](maintenance/A14_REFINEMENT_ROADMAP.md)。本页描述当前源码；切歌开关、隐藏暂停态修复与分组整理尚未包含在已发布的 [r14.25.1](https://github.com/thetvplus/customiuizer-a14/releases/tag/r14.25.1) 中，主机、ROM、APK 与设备证据分别记录。
