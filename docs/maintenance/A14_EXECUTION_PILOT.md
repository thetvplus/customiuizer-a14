## 测量口径

在同一 Windows 工作区、JDK 25、现有 SDK 和已填充 Gradle 缓存下，对不改变业务源码的代表性检查做命令回放。记录墙钟、实际退出状态及测试报告；本次规则和文档变化后的检查不声称是一次独立开发任务的耗时。没有启动第二套 Agent 或自动化框架。

旧文档策略本来已有三项静态检查，前后沿用相同范围。叶子 Python 工具对照旧的统一 Full / 全量 Python 收口与新的定向工具检查；Standard 对照完整检查与关联 JVM 类。Deep 复用同一份完整验证，Release 只审规则与既有 CI 证据，不触发正式操作。

测量原始日志与逐命令收据留在工作区忽略目录 `.di-evidence/execution-policy-20261025/`，不入库。本页只保留可复核摘要；数据不足时不宣称整体任务提速、失败率下降或设备性能改善。

## 路由验收与限制

| 输入及触发 | 按新规则应执行 | 本次核对 |
| --- | --- | --- |
| 只修 Markdown 链接 | Quick 文档三项，不启动 JVM / DexSQL / ADB | 三轮实测，检查均通过 |
| 只改独立 APK 报告工具的预算计算 | Quick，查真实消费者并跑工具行为测试 | 已查 Python 引用，只有对应测试消费者；原断言不变，3 项通过 |
| 页面导航调用跨 Fragment / 搜索页 | Standard，关联行为测试并保留源码门禁 | 四类共 35 项通过；不推广到无关模块 |
| 单行改 JDK / R8、共享偏好安装或签名门禁 | Deep；正式执行另走 Release | 按契约升级，不按小 diff 降级；相应脚本、断言、工作流完全未改 |
| 文档与 R8 输入混合修改 | Deep 并覆盖文档范围 | 规则明确按最高实际风险取并集，不能归入文档例外 |
| HEAD 只增加文档提交 | 证明应用 / 构建 / 检查输入等价后复用原通过结果 | 本分支相对基线的上述输入无 diff；提交与报告不触发再跑完整验证 |
| 已提交源码仍用 `--changed` | 不接受该范围作为完整分支证明 | TESTING 明确要求无 changed 的对应检查及 exact base/head diff |

本次实际修改只有 Markdown 规则与 Skill，业务、构建、工具及测试输入与基线等价；本机 Full / 工具测试及同源码 main CI 的 R8 结果可按范围复用。文档和 Skill 自身另以当前文件检查。现有 CI 与正式发布断言没有删改。

测量固定先跑旧 Full / 全量工具，再跑定向路径，未做交叉顺序、冷缓存对照或多轮独立 Codex 开发任务。这里证明的是已选验证路径的实际成本和覆盖差异，不能证明模型总体效率、错误率或任意任务的回归覆盖不变。历史完整聊天不足，无法同比总耗时、模型工具调用数、重复检索 / 确认次数与等待时间；本轮不为模式选择请求用户确认。

目前只保留本项目试点。后续若需要整体效率结论，应在同类真实任务、相同模型 / 工具 / 环境与明确影响范围下记录完整调用轨迹，比较总耗时、重复读取 / 确认、检查 / 等待时间及修复后的失败情况；不为制造数据重复正式发布或扩大权限。试点结论限于上述证据范围。
